# ТЗ — Samba

## 1. Назначение

Учитывать контроллеры Samba AD и управлять ими с рабочего стола: каталог домена, шары и перенос отмеченных записей Main. XOS не устанавливает Samba. Пароли домена в ответах API не возвращаются.

## 2. Модель

| Сущность | Смысл |
|----------|--------|
| `samba_server` | Карточка DC: владелец, роль `ad_dc`, шары (`file`), часовой пояс, адрес агента, токен установки, снимок каталога, правила импорта |
| `samba_server_access` | Права другого пользователя |
| `samba_enrollment` | Одноразовый секрет установки, около 30 минут |
| `samba_agent_credential` | Секрет агента после enroll |
| `samba_command` | Очередь: тип, аргументы, статус, результат |

Роль NT4 API не принимает.

Токен установки хранится на сервере и пишется в `agent.ini` при сборке архива. Смена токена действует со следующей установки. В API наружу уходит только признак, что токен задан.

## 3. Доставка команд

1. Если у сервера заполнен адрес агента, центр открывает к нему WebSocket и передаёт одну команду. Секрет — токен установки.
2. Иначе команда уходит в хаб `php bin/console samba:agent-hub` (`SAMBA_AGENT_HUB`, по умолчанию `http://127.0.0.1:8766`), если агент сам подключил WebSocket к XOS.
3. Иначе команда ждёт long-poll.

Несколько команд импорта ставятся в очередь одним пакетом. Центр будит агента один раз, дальше очередь разбирается по порядку. Пароль новой учётки шифруется ключом агента и в журнал не попадает.

## 4. Каталог

Снимок — полный поиск по `sam.ldb`: подразделения, пользователи (`displayName`), группы (описание и DN участников). Он хранится на сервере вместе со временем синхронизации. Кнопка «Обновить» и ежечасное обновление по heartbeat перечитывают каталог. Создание, удаление и перенос правят снимок сразу.

Без снимка импорт не стартует: иначе нельзя отличить новую учётку от уже существующей.

## 5. Импорт из Main

Источник — выбранные подразделения Main. Переносятся только записи с отметкой **«В домене»** на карточке пользователя, группы или подразделения. Импорт сохраняет эти отметки для показанного списка.

Если подразделение снято, его пользователи и группы не переносятся, даже когда у них самих отметка включена.

Куда кладутся новые записи:

- подразделение — в корень домена, имя берётся из кода Main;
- пользователь и группа своего подразделения — внутрь этого подразделения;
- остальные новые пользователи и группы — в `CN=Users`.

Имя учётки — логин, имя группы — код. Пароль новой учётки равен логину. Логин короче 8 символов для новой учётки не годится: такая запись пропускается. Если имя уже есть в снимке, меняются только поля, пароль не трогается. Участники добавляются. Лишние участники домена не снимаются.

Правила полей хранятся на сервере (`import_map`). По умолчанию у пользователя: имя → `givenName`, фамилия → `sn`, псевдоним → `displayName`, почта → `mail`, телефон → `telephoneNumber`, описание → `description`. У группы описание → `description`. Пустое значение поле в домене не стирает.

## 6. Шары и конфиг

Шаблон `smb.conf` собирается по образцу Zentyal и сохраняет `dns forwarder`, ключи `tls` и `idmap config`. Netlogon и sysvol остаются. Шары пишутся в отдельный файл (`shares_conf`, по умолчанию `/etc/samba/xos-shares.conf`): `force create mode = 0660`, `force directory mode = 0770`, `vfs objects = acl_xattr`, список чтения, необязательная корзина. Домашние каталоги включаются маркером `# xos-homes`. После записи конфиг проверяется `testparm`; при ошибке файл возвращается.

## 7. Права

Чужому пользователю с `ROLE_SAMBA` можно выдать `view`, `shares`, `directory`, `provision`, `manage`. Журнал, токен, передача владения и импорт — у того, кто управляет сервером. Право `log` в выдаче отвечает 400. Удаление пользователя Main, у которого есть серверы, отвечает 409, пока владение не передано.

## 8. UI

Окно `samba-servers`. Карточка объекта домена — отдельное окно. Импорт: подразделения Main, какие из них переносить, пользователи и группы только из переносимых подразделений, таблица правил полей, запуск.
