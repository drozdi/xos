# ТЗ — инфоблоки

## 1. Назначение

Собрать произвольный каталог без новой таблицы: тип задаёт род данных, блок — конкретный справочник, раздел — дерево внутри блока, свойство — поле, элемент — запись.

Готовые окна заметок, статей, FAQ, галереи, объявлений, контактов, услуг, идей, лидов и рецептов — элементы блоков типа `content`, а не отдельные API.

## 2. Тип, блок, раздел

Тип имеет код. Блок ссылается на тип и имеет свой код (`notes`, `articles`, …). Раздел принадлежит блоку и может быть вложен. У раздела свой набор свойств (`section-property`), отличный от свойств элементов.

Фильтр раздела: `GET /api/iblock/section/{id}/filter`. Элементы раздела: `POST /api/iblock/section/{id}/elements`.

## 3. Свойства

Свойство описывает поле элемента: код, тип, подпись. Для списков есть значения `property-enum`. Каталог контента читает значения свойств и рисует поля формы из конфига, не из отдельной таблицы.

## 4. Элемент

Элемент — запись блока. Его можно отдать другому пользователю: `POST /api/iblock/element/{id}/share` и `DELETE .../share/{userId}`.

Список элементов фильтруется по блоку. Контент-окно само находит блок по коду и не просит пользователя открывать конструктор.

## 5. Рецепты

Окна `recipes`, `recipe`, `recipe-categories` смотрят роль `recipe`. Данные те же элементы инфоблока. Категории рецептов — разделы блока `recipes`.

Картинка рецепта — поле элемента `detail_image`. Галерея — множественное свойство `COVER`. В списке превью берётся из `detail_image`, иначе из первого файла `COVER`.

## 6. Критерии

- [x] CRUD типа, блока, раздела, свойства, значения и элемента
- [x] Раздел отдаёт фильтр и свои элементы
- [x] Элемент можно расшарить и забрать доступ
- [x] Каталоги контента открываются как обычные приложения «Пуска»
- [x] Рецепты закрыты ролью `ROLE_RECIPE`
