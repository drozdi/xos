# ТЗ — администрирование

## 1. Назначение

Дать администратору завести пользователей, разложить их по группам и подразделениям, выдать роли и scope, посмотреть журнал.

## 2. Пользователь

Карточка хранит логин, имя, пароль, роли и членство. Пароль меняется в теле обновления, отдельного метода смены пароля нет. Выбор для чужих селектов — `POST /api/main/user/select`, он не требует полного экрана пользователей.

Список ролей для формы: `GET /api/main/user/role-options`.

## 3. Группы и подразделения

Группа — именованный набор пользователей для шаринга календарей, задач и классов.

Подразделение — дерево организации. У пользователя одно подразделение. Активное подразделение сессии хранится не в карточке, а в user-data `main.active_ou_id`, чтобы один человек мог переключать контекст без правки учётки.

## 4. Права

Источник прав — `server/src/<Модуль>/setting.json`: claimant и биты `map-access`. Команда `main:claimant:sync` копирует это в таблицы claimants. Экран `main-claimants` показывает копию. Правка карточки меняет БД; следующий sync может вернуть значения из файла. Модуль, которого больше нет на диске, теряет опции доступа, строка claimant остаётся.

Защищённый модуль дополнительно требует роль `ROLE_<МОДУЛЬ>`. Список таких модулей общий для сервера и клиента.

## 5. Журнал

`GET` или `POST /api/main/audit/list` читает записи аудита. Отдельной записи из этого экрана нет.

## 6. Файлы

Загрузка общих файлов модулей живёт в Main: `POST /api/main/file/upload`. Белый список модулей — в [../API.md](../API.md).

## 7. Критерии

- [x] CRUD пользователей, групп, подразделений и claimants
- [x] Роли и scope видны в карточке пользователя
- [x] Активное подразделение хранится в user-data и не затирает карточку
- [x] Каталог прав собирается из `setting.json`
- [x] Журнал открывается отдельным окном
