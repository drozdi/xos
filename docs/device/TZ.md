# ТЗ — устройства

## 1. Назначение

Вести учёт техники организации: тип, свойства типа, учёт (в том числе списание), место, комплектующие, установленные программы и лицензии.

## 2. Роли

Роль `ROLE_DEVICE`. Методы помечены scope `can_read` и соседними правами модуля. Без роли окна устройств в «Пуске» не открываются.

## 3. Устройство

Карточка: название, код, тип, описание, учёт, места, ремонты, свойства, лицензии, изображения.

Тип обязателен для списка. Набор свойств зависит от типа. Изображения загружаются методами upload модуля `device` и общим файловым upload с `module=device`.

Списание — признак учёта `discarded`. В списке по умолчанию списанные не показываются. Включение «Списан» показывает только списанные. Устройство без записи учёта при выключенном флажке остаётся в списке.

## 4. Подразделение

Активное подразделение пользователя не ограничивает `POST /api/device/device/list`. Поля фильтра `ou` и `ou_id` сервер снимает до выборки.

Выборка для селектов `POST /api/device/device/select` активное подразделение применяет.

## 5. Справочники

Типы устройств, свойства, типы комплектующих, программы и типы программ, лицензии и ключи. Справочник правится отдельным окном и подставляется в карточку.

У типа есть привязка свойств и допустимых комплектующих (`/api/device/types/properties`, `/api/device/types/components`).

## 6. Комплектующие

Отдельный список. Как и устройства, при открытии выбирается первый тип. Комплектующее связано с родительским устройством или учётом. Форма свойств: `GET /api/device/subDevices/form/{id}`.

## 7. Учёт

`POST /api/device/accounting/list` и `POST /api/device/accounting/list/select` — операции и выборка учёта, не отдельное окно «Пуска».

## 8. Критерии

- [x] CRUD устройства и справочников
- [x] Список открывается на первом типе, без пункта «Все типы»
- [x] Список не фильтруется по `ou` / `ou_id`
- [x] Списанные скрыты, пока не выбран «Списан»; устройства без учёта при этом видны
- [x] Файлы изображений через upload модуля `device`
