# ТЗ — продукт XOS

## 1. Назначение

XOS — рабочий стол в браузере. Пользователь входит, видит стол, панель задач и меню «Пуск», открывает приложения в окнах. Данные приложений хранятся на сервере и доступны с другого устройства после входа.

Продукт состоит из оболочки и модулей. Оболочка не знает предметных правил модулей. Модуль не рисует стол и не хранит геометрию окон.

## 2. Состав

| Слой | Где | Что делает |
|------|-----|------------|
| API | `server/` | Symfony 7, JWT, модули `server/src/<Модуль>` |
| Оболочка | `client/src/core/` | Окна, Пуск, настройки, синхронизация сессии |
| Приложения | `client/src/apps/` | Окна. Манифест — `index.ts` в папке приложения |
| Предметная логика клиента | `client/src/features/` | Запросы, доступ, общие экраны домена |

Модуль подключается своими `config/routes.yaml`, `services.yaml` и `doctrine.yaml`. Каталог прав — `setting.json`. Команда `php bin/console main:claimant:sync` переносит claimants в БД. Если файл и БД разъехались, процесс пишет предупреждение в лог. Строка claimant без модуля остаётся, но теряет `access_options`.

Защищённые модули перечислены в `server/src/App/Security/ProtectedAppModules.php` и `client/src/core/auth/protectedApps.ts`. Списки должны совпадать.

Описание каждого домена: `docs/<домен>/README.md`, `TZ.md`, `API.md`. Индекс — [README.md](README.md).

## 3. Вход и права

- Вход: `POST /api/login`. Тело — логин и пароль. Ответ — access-токен.
- Обновление: `POST /api/token/refresh`.
- Выход: `POST /api/logout`.
- Дальнейшие методы, кроме явно открытых, требуют `Authorization: Bearer <access>`.
- Защищённый модуль требует роль `ROLE_<МОДУЛЬ>` и scope `can_*` на методе.
- Карта прав текущего пользователя: `GET /api/account/accesses` и `GET /api/account/map`.
- Справочник scope: `GET /api/scope/map`, `GET /api/scope/accesses`.

Ошибки: `400` с `message` и `violations`, `401` без токена или с просроченным, `403` без роли или scope, `404` если запись не найдена.

## 4. Оболочка

Подробности — [system/TZ.md](system/TZ.md). Для продукта обязательны такие правила:

- Окна перетаскиваются. Бросок к краю стола ставит окно на половину, в угол — на четверть.
- Виджеты остаются внутри рабочего стола.
- Четыре страницы виджетов. Переключение: Настройки → Виджеты или Ctrl+Alt+стрелки.
- Поиск Ctrl+K ищет приложения, списки задач, карточки доски, заметку в первой базе знаний и файлы `home://`.
- Закрытие окна убирает его из истории запуска и из сохранённой геометрии. Обновление вкладки историю не стирает.
- Меню «Пуск»: группы по `START_MENU_GROUP_SORT`. Порядок: Администрирование, Система, Стандартные, Инфоблоки, затем остальные. Высота списка программ равна оставшемуся месту панели, последний пункт не обрезается фиксированной высотой.

## 5. Общие хранилища

| Хранилище | Зачем |
|-----------|--------|
| `/api/desktop-state` | Настройки USER/APP/WIN и последний путь проводника |
| `/api/user-data` | Произвольные prefs приложений (`code` + JSON) |
| `/api/settings` | Отдельные ключи настроек |
| `/api/main/file/upload` | Файлы модулей из белого списка |

Категории снимка стола: `USER` (тема, виджеты, страница стола), `APP` (`launchHistory`), `WIN` (`{appId}/{windowId}`).

Списки новых методов читают `page` и `size`. Старые списки по-прежнему принимают `limit` и `offset`. Разбор обоих форматов: `App\Http\PageQuery`.

Клиент для необязательных ключей user-data один раз читает весь список и дальше ищет в памяти. `GET /api/user-data/{code}` при отсутствии ключа отвечает `404`.

## 6. Модули

| Модуль | Роль | Назначение |
|--------|------|------------|
| Main | `ROLE_MAIN` | Пользователи, группы, подразделения, права, журнал |
| Device | `ROLE_DEVICE` | Техника, комплектующие, программы, лицензии |
| Explorer | `ROLE_EXPLORER` | Диски и файлы пользователя |
| SchoolTask | `ROLE_SCHOOLTASK` | Классы, расписание, домашние задания |
| IBlock | `ROLE_IBLOCK` | Конструктор каталогов и контент поверх типа `content` |
| Recipe | `ROLE_RECIPE` | Доступ к рецептам внутри инфоблоков, своего API нет |
| IncCom | `ROLE_INCCOM` | Счета, операции, переводы, чеки |
| Calendar | `ROLE_CALENDAR` | Календари и события |
| Todo | достаточно входа | Списки задач. Модуль не в списке защищённых, scope на списках |
| Board | `ROLE_BOARD` | Доски, колонки, карточки |
| PKB | `ROLE_PKB` | Базы знаний, заметки, граф |
| Inbox | `ROLE_INBOX` | Внутренние сообщения |
| Github | `ROLE_GITHUB` | Токен и issues GitHub |
| TeamStorm | `ROLE_TS` | Прокси TeamStorm |

Привычки своей роли и таблиц не имеют: отметки лежат в user-data, окно открывается вместе с задачами.

Активное подразделение (`main.active_ou_id` в user-data) задаётся в настройках и применяется теми списками, которые сами вызывают `OuScope`. Список устройств `POST /api/device/device/list` подразделение не применяет: поля `ou` и `ou_id` из фильтра отбрасываются.
